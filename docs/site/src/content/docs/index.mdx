`core-vcs` gives a Go agent a pure-Go [go-git](https://github.com/go-git/go-git) working copy and a set of neutral verbs — `clone`, `commit`, `publish`, `proposal-create`, `proposal-view`, `proposal-comment`, `proposal-update`, `proposal-close` — that a provider package translates to one forge's API:

| Provider | Package | Covers |
|---|---|---|
| `github` | `github.com/go-steer/core-vcs/providers/github` | `github.com` and GitHub Enterprise Server (`/api/v3`) |
| `gitlab` | `github.com/go-steer/core-vcs/providers/gitlab` | `gitlab.com` and self-managed GitLab (`/api/v4`, private CA supported) |
| `git` | `github.com/go-steer/core-vcs/providers/git` | Any bare Git remote over HTTPS (`publish` + optional compare link via `ProposalURLTemplate`) |

## Core guarantees

<CardGrid>
  <Card title="Neutral vocabulary" icon="approve-check">
    A change offered for review is a **proposal**. Pull request and merge request appear only inside a provider's `ProposalNoun` string — never in exported types, verbs, or error codes.
  </Card>
  <Card title="The agent never writes the target branch" icon="warning">
    `Workspace.Publish` refuses `TARGET_IS_BRANCH` and `BRANCH_NOT_OURS` in memory before any network call. There is no force-push verb and no option that relaxes the guards.
  </Card>
  <Card title="Pure Go, distroless-ready" icon="seti:go">
    Local verbs (`Status`, `Diff`, `Log`, `Branch`, `Commit`) run over `go-git` with zero shell-outs to a `git` binary. Forge verbs use thin `net/http` clients with no vendor SDKs.
  </Card>
  <Card title="Shared object cache across sessions" icon="rocket">
    Set `Policy.CacheDir` so concurrent sessions and multiple agent processes share a single bare packfile store per repository via `flock` and read-through overlay storage.
  </Card>
</CardGrid>
